## 使用规则

每张方法卡包含：正式名称/来源、回答与不回答、职能、对象与尺度、输入输出、德鲁克/TPS关系、证据要求、常见误用和检索触发。

尺度缩写：

- **层级**：宏观、行业、企业/组合、业务/产品、组织/团队、价值流/流程、任务/事件、个人行为。
- **颗粒度**：粗（方向/系统）、中（能力/组件/流程段）、细（事件/行为/样本）。
- **关系**：语义映射、互补校验、执行衔接、张力冲突、层级错配。
- **摘要**：A=直接依据，B=有据可查的影响/后生发展，C=独立方法的有界映射，D=不支持/冲突/错配。

表中摘要是默认起点。当前用法、组件或新证据可以改变判断，但升级到 A/B 必须给出一手或可靠谱系证据。

| **PESTLE / 环境扫描**；谱系常追溯 [Aguilar 1967](https://books.google.com/books/about/Scanning_the_business_environment.html?id=sn1EAAAAIAAJ)，缩写无可核实单一创建者 | 宏观变化及其影响；不决定行业利润、战略取舍或执行 | 描述；宏观→企业；2–10年；粗 | 法规、政策、经济、社会、技术、环境信号 → 变化、影响链、关键假设 | 德：互补校验 C；TPS：层级错配 D | 必须使用当期外部证据；误用为无证据检查清单；声称 Aguilar“发明 PESTLE”时核验 |
| **Porter Five Forces**；[Porter 1979](https://hbr.org/1979/03/how-competitive-forces-shape-strategy) | 行业利润结构与议价力量；不回答企业独特资源、宏观突变和执行 | 诊断；行业→业务；3–5年；中 | 行业边界、集中度、替代、壁垒、转换成本 → 结构诊断与定位议题 | 德：互补校验 C；TPS：层级错配 D | 需当前行业数据；误用为直接竞争者清单、五力等权或静态结论 |
| **Scenario Planning**；Shell/Pierre Wack，[Shell回顾](https://www.shell.com/news-and-insights/scenarios/what-are-shell-scenarios/_jcr_content/root/main/section_509167378/promo/links/item0.stream/1652289755448/a0e75f042fee5322b72780ee36e5ba17c35a4fc6/shell-scenarios-40yearsbook080213.pdf) | 多种可信未来下何种选择更稳健；不预测“最可能未来” | 评估；宏观/企业组合；5–20年；粗—中 | 驱动因素、既定趋势、不确定性、决策 → 情景、路标、备选动作 | 德：互补校验 C；TPS：互补校验 C/层级错配 D | 必须检索当期驱动因素；误把情景当预测、愿景或故事集 |
| **Wardley Maps**；[Simon Wardley](https://www.swardleymaps.com/) | 用户需要、组件依赖与演化地形；不证明因果或给出流程细节 | 描述/生成；业务/产品生态；1–5年；中 | 用户需要、依赖、演化证据 → 地图、气候、原则、行动假设 | 德：语义映射 C；TPS：互补校验 C | 需当前生态和演化证据；误作架构图、成熟度矩阵或价值流图 |
| **OODA**；John Boyd，[原始简报档案](https://www.coljohnboyd.com/static/documents/1986-12__Boyd_John_R__Patterns_of_Conflict__PDF.pdf) | 对抗与不确定中如何持续重构认知并行动；不决定组织目的和长期组合 | 执行/学习；任务→组织；秒—月；细、循环 | 观察、经验、文化、模型、对手反馈 → 新定向、选择与行动 | 德：语义映射 C；TPS：执行衔接 C | 误作线性四步或“越快越好”；与 PDCA/TPS血缘表述时核验 |
| **Theory of Constraints / Five Focusing Steps**；Eliyahu Goldratt，[官方说明](https://www.goldrattresearchlabs.com/introduction-to-toc) | 什么约束限制系统目标；不替组织决定目标或价值边界 | 诊断/执行；流程→企业/供应链；持续；中—细 | 系统目标、吞吐、库存、费用、流量 → 识别、利用、服从、提升约束 | 德：互补校验 C；TPS：互补/张力 C/D | 误把每个瓶颈都称约束、只加产能、忽略约束迁移；不能称 TPS同义方法 |
| **Strategic Choice Cascade**；Lafley/Martin，[创建者说明](https://rogerlmartin.com/thought-pillars/strategy) | 取胜愿景、在哪竞争、如何赢、能力和系统是否一致；不替代事实验证和运营设计 | 生成/评估；企业/业务；1–5年；中 | 顾客、竞争、经济性、能力假设 → 五项相互约束的选择 | 德：语义映射 C；TPS：执行衔接 C | 误作事后填表、口号和能力清单；关键选择必须有外部证据 |
| **Resource-Based View / VRIN**；[Barney 1991](https://journals.sagepub.com/doi/10.1177/014920639101700108) | 哪些资源可能形成持续优势；不证明顾客付费或优势不会衰减 | 诊断；企业/业务；3–10年；中 | 价值、稀缺、难模仿、不可替代证据 → 战略资源和投资缺口 | 德：语义映射 C；TPS：层级错配 D | 误把所有长处称独特资源；VRIN/VRIO版本或原始出处表述时核验 |
| **BCG Growth-Share Matrix**；[Bruce Henderson 1970](https://www.bcg.com/publications/1970/strategy-the-product-portfolio) | 多业务现金和资源配置议题；不凭增长/份额单独判断使命、协同与吸引力 | 评估；企业组合；2–7年；粗 | 相对份额、增长、现金需求/产出 → 投资、维持、收割、退出议题 | 德：语义映射 C；TPS：层级错配 D | 误把象限当绩效评级、机械杀“瘦狗”、默认份额必然带来利润 |
| **Ansoff Product-Market Matrix**；[Ansoff 1957](https://books.google.com/books/about/Strategies_for_Diversification.html?id=_opJvwEACAAJ) | 从产品/市场新旧生成增长方向；不比较真实吸引力、能力和竞争反应 | 生成；企业/业务；1–5年；粗 | 产品/市场边界、风险和能力 → 四类增长选项 | 德：语义映射 C；TPS：层级错配 D | 误把2×2当结论、模糊“新”的边界、假定风险线性递增 |
| **Blue Ocean Strategy Canvas / ERRC**；[官方工具](https://www.blueoceanstrategy.com/tools/strategy-canvas/) | 如何重构竞争因素、提高买方价值并降低成本；不证明需求、可行性和防御性 | 生成；业务/产品；1–5年；中 | 替代方案、竞争因素、成本、非顾客证据 → 价值曲线与删减增创 | 德：语义映射 C；TPS：执行衔接 C | 误解为“没有竞争”、只做功能脑暴；需验证非顾客和经济性 |
| **Cynefin**；Dave Snowden，[官方说明](https://thecynefin.co/about-us/about-cynefin-framework/) | 因果情境适合标准化、专家分析、试探还是先稳定；不直接给出战略答案 | 研究辅助/执行路由；任意层级；即时—长期；粗 | 因果可知性、稳定性、约束和证据 → 情境域与响应模式 | 德：互补校验 C；TPS：互补校验 C | 误作永久标签或用“复杂”逃避责任；分类变化需按当前情境重判 |
| **Balanced Scorecard**；Kaplan/Norton，[1992原文](https://hbr.org/1992/01/the-balanced-scorecard-measures-that-drive-performance-2) | 如何把战略转成目标、指标和反馈；不创建战略或证明因果链 | 执行；企业→团队；1–5年、月/季反馈；中 | 已选战略、价值主张、因果假设 → 战略图、指标、目标、行动 | 德：执行衔接 C；TPS：执行衔接 C | 误作KPI拼盘、复制通用指标、先定指标后补战略；指标值不得凭空生成 |

## 组织、决策与创新

| 方法与来源 | 回答 / 不回答 | 职能；对象与尺度 | 输入 → 输出 | 与德鲁克 / TPS关系 | 证据、误用与检索触发 |
|---|---|---|---|---|---|
| **OKR**；Andy Grove形成、John Doerr传播，[What Matters](https://www.whatmatters.com/okrs-explained/) | 本周期聚焦什么、如何验收；不回答战略为何正确、工作如何流动 | 执行；个人→组织；季度/年度；目标—结果级 | 已选战略、基线、责任 → Objective与KR | 德：语义映射 C；TPS：执行衔接 C | 误把任务、KPI或奖金表当KR；不能称MBO现代版或德鲁克原生 |
| **RACI / DACI**；RACI无可核实单一创建者；[DACI操作版本](https://www.atlassian.com/team-playbook/plays/daci) | 谁执行、谁负责或谁拍板；不判断方案优劣和顾客价值 | 执行；组织/团队；单个流程或决策；角色级 | 任务/决策清单、利益相关者 → 权责矩阵 | 德：语义映射 C；TPS：执行衔接 C | 误让多人共同拍板、用矩阵代替协作；创建者/历史说法必须核验 |
| **RAPID**；Bain Rogers/Blenko，[HBR 2006](https://hbr.org/2006/01/who-has-the-d-how-clear-decision-roles-enhance-organizational-performance) | 复杂决策中的推荐、输入、同意、决定和执行权；不保证判断正确 | 执行；跨职能/组织；单次重大决策；角色级 | 决策议题、相关者、约束 → 决策角色配置 | 德：语义映射 C；TPS：执行衔接 C | 误让Agree角色泛滥、把RAPID理解为“越快越好” |
| **COM-B / Behaviour Change Wheel**；Michie等，[2011原始论文](https://pubmed.ncbi.nlm.nih.gov/21513547/) | 能力、机会或动机如何限制目标行为；不回答行为是否值得推动或组织目的是否正当 | 诊断/生成；个人行为/制度环境；周—月；细 | 明确行为、障碍证据 → 行为诊断、干预函数 | 德：互补 C/张力 D；TPS：互补 C | 误把标签当诊断、只做培训或操控员工；伦理和自主性冲突时判D |
| **Premortem**；Gary Klein，[HBR 2007](https://hbr.org/2007/09/performing-a-project-premortem) | 假设计划已失败，可能为何；不估算概率或替代风险量化 | 反证；项目/决策团队；启动前；风险假设级 | 计划、多元成员、约束 → 失败原因和缓解动作 | 德：互补校验 C；TPS：互补校验 C | 误变唱衰会、领导先给答案、无责任人；不得称TPS标准工具 |
| **Design Thinking**；无单一发明者，[IDEO源流](https://designthinking.ideo.com/introduction) | 如何理解人、重构问题、生成并试验方案；不证明商业、技术或财务可行 | 诊断/生成；用户体验/产品服务；天—月；洞察—原型级 | 观察、访谈、约束 → 问题框定、概念、原型、反馈 | 德：语义映射 C；TPS：互补校验 C | 误把工作坊当创新、同理心当事实、跳过验证；发明者说法需核验 |
| **Jobs to Be Done**；多流派，此处以 [Christensen Institute](https://www.christenseninstitute.org/theory/) 为代表 | 顾客在何种情境下“雇用”方案取得何种进展；不回答市场规模、利润或实现方式 | 诊断；顾客情境/产品；事件—生命周期；job级 | 行为、访谈、替代选择 → job、力量、障碍和机会 | 德：语义映射 C；TPS：执行衔接 C | 误把job写成产品功能或人口画像；流派/创建者表述时核验 |
| **Psychological Safety**；Amy Edmondson，[1999论文记录](https://inclusionandbelongingtaskforce.harvard.edu/publications/psychological-safety-and-learning-behavior-work-teams) | 团队是否敢暴露问题、求助和承担人际风险；不等于舒适、同意或免绩效责任 | 诊断/执行；团队；持续；信念/行为级 | 行为证据、调查、事件 → 风险点和领导行为 | 德：互补校验 C；TPS：执行衔接 C | 误成“不能批评”、福利氛围或单次打分；调查不能替代行为证据 |
| **Double-Loop Learning**；Chris Argyris，[HBR 1977](https://hbr.org/1977/09/double-loop-learning-in-organizations) | 错误应修改行动还是挑战目标、政策和支配变量；不直接给出新目标 | 诊断/学习；个人→组织制度；复盘—多年；假设级 | 结果偏差、推理过程、治理变量 → 行动修正或规则重构 | 德：语义映射 C；TPS：互补校验 C | 误把任何复盘称双环、无限质疑而不行动 |
| **Kotter 8 Steps**；John Kotter，[官方方法](https://www.kotterinc.com/methodology/8-steps/) | 大规模变革如何动员、行动并制度化；不判断变革方向是否正确 | 执行；组织/生态；月—年；变革阶段级 | 变革机会、阻力、相关者 → 联盟、愿景、行动与短期成果 | 德：执行衔接 C；TPS：执行衔接/张力 C/D | 误作线性打卡或只做沟通；运动式变革替代日常改善时有张力 |
| **Self-Determination Theory**；Deci/Ryan，[工作场景研究](https://www.selfdeterminationtheory.org/SDT/documents/2001_DeciRyanGagneLeoneEtal.pdf) | 自主、胜任、联结如何影响动机内化；不决定绩效标准、岗位匹配或战略 | 诊断；个人/工作环境；月—年；心理需要级 | 制度与体验证据 → 动机机制假设和设计约束 | 德：语义/互补 C；TPS：互补 C | 误把自主等同放任、用奖励替代工作设计；不能因“尊重人”相似升级血缘 |
| **Stage-Gate**；Robert Cooper，[官方模型](https://www.stage-gate.com/about/stage-gate-innovation-performance-framework/discovery-to-launch-process/) | 创新项目如何分阶段学习并Go/Kill/Hold/Recycle；不产生好创意或保证市场成功 | 评估/执行；产品项目/组合；月—年；阶段/投资门级 | 市场、商业、技术证据 → 门评决策和资源承诺 | 德：执行衔接 C；TPS：执行衔接/张力 C/D | 误作官僚审批、固定瀑布或只准Go；僵化批次交接与流动有张力 |
| **Voice of Customer / QFD前端**；[Griffin/Hauser 1993](https://pubsonline.informs.org/doi/10.1287/mksc.12.1.1) | 顾客需要是什么、如何组织和排序；不自动回答取舍、利润和未来隐性需求 | 描述/诊断；顾客群/产品团队；研究周期；需求层级 | 访谈、排序、竞争感知 → 需求层级和优先级 | 德：语义映射 C；TPS：执行衔接 C | 误用提及频率代替重要性、让内部人替顾客发声；需真实顾客证据 |

|---|---|---|---|---|---|
| **PDCA / PDSA**；Shewhart奠基、Deming发展PDSA，[Deming Institute](https://deming.org/explore/pdsa/) | 某个改变是否产生预测中的学习；不单独确定战略优先级或根因 | 执行/学习；流程/团队；天—月；单一假设级 | 目标、理论、预测、指标 → 学习、调整、下一轮试验 | 德：语义映射 C；TPS：执行衔接 C | 误把Check当审计、无预测或不更新标准；不是TPS原生方法 |
| **A3 Problem Solving**；Toyota后生实践，[Lean Enterprise Institute](https://www.lean.org/lexicon-terms/a3-report/) | 如何围绕一个具体差距形成事实、原因、对策和跟进的共同理解；不替代技术专科分析 | 诊断/执行/学习；负责人/团队；天—月；单问题级 | 目标差距、现场事实、因果证据 → A3叙事、行动和跟踪 | 德：执行衔接 C；TPS：后生发展 B | 误作填模板或事后包装；“TPS原生支柱”主张必须降级 |
| **Value Stream Mapping**；源于Toyota物料与信息流图，Rother/Shook系统化，[Learning to See](https://www.lean.org/wp-content/uploads/2021/01/Learning-to-See-introduction.pdf) | 端到端物料与信息如何流动、等待和断裂；不自动证明根因或顾客价值 | 描述/生成；价值流；当前—未来数月；流程块级 | 需求、CT/LT、WIP、信息触发 → 当前图、未来图、实施计划 | 德：互补校验 C；TPS：后生/有据影响 B | 误作墙纸、只画工序不画信息流、与Wardley Maps混同 |

| **SIPOC**；无公认单一创建者，[ASQ](https://asq.org/quality-resources/articles/sipoc-job-aid?id=232019f796fc447dad7cdb2cf242f48a) | 流程边界、供应者、输入、输出和顾客是谁；不回答详细流程、根因、等待与波动 | 描述；流程边界；半天—数天；粗 | 初步边界、相关者、需求 → 高层范围图 | 德：语义映射 C；TPS：执行衔接 C | 误把内部部门全称顾客、画得过细或不验证输入输出；谱系说法需核验 |
| **Agile Manifesto**；17位软件实践者，[官方原则](https://agilemanifesto.org/principles) | 复杂产品开发采用什么价值取向和反馈原则；不定义具体角色、流程或统计方法 | 执行原则；产品/团队；持续；原则级 | 用户价值、变化、工作成果 → 增量交付、反馈和自组织改善 | 德：语义映射 C；TPS：语义/执行衔接 C | 误解为不计划、不文档或只追速度；外部软件运动，非TPS |
| **Scrum**；Schwaber/Sutherland，[Scrum Guide](https://scrumguides.org/scrum-guide.html) | 复杂工作如何以透明、检视、适应交付增量；不规定工程方法、质量工具或流程效率 | 执行；产品团队；Sprint≤1月；事件/工件级 | Product Goal、Backlog、能力 → Sprint Goal、Increment、更新Backlog | 德：执行衔接 C；TPS：执行衔接/张力 C/D | 误只保留会议、速度当绩效、固定范围压Sprint；批次掩盖流动时有张力 |

## 方法链与检索规则

### 使用最小方法链

一个方法通常只完成一段工作。按证据缺口组合，而不是把方法揉成混合框架：

- 环境证据：PESTLE/情景 → 行业结构：五力 → 战略生成：选择级联/Ansoff/蓝海 → 资源评估：RBV/BCG → 目标执行：BSC/OKR。
- 流程边界：SIPOC → 现实重建：BPMN/VSM/服务蓝图 → 诊断：TOC/FMEA/SPC → 执行学习：A3/PDSA/Scrum/Kanban/AAR。
- 行为问题：COM-B/SDT → 责任与决策接口：RACI/DACI/RAPID → 团队条件：心理安全 → 行动与反馈。

默认每阶段一个主方法、最多一个辅助方法。必须说明前一方法输出如何成为后一方法输入。

### 强制联网核验

- 名称不在本表，或存在流派、版本、创建者和谱系争议。
- 用户询问“谁发明、源自哪里、原话、官方定义”。
- 准备把完整方法或组件判为 A/B。
- 方法定义可能随版本变化，如 Scrum Guide、标准或监管方法。
- 应用依赖当前市场、法规、客户、竞争、技术或生态数据。

本表中的链接用于方法校准，不证明外部方法与德鲁克/TPS存在历史传承。找不到可信来源时，标记“尚未证实”，不得补造来源或把相似性升级成血缘。
