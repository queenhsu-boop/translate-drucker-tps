生成内容前，必须在 `ASK_ONE`、`WAIT_EVIDENCE`、`DELIVER` 中选择且只选择一个。前两个是终止状态，不得附加正式分析或老板汇报。

## `ASK_ONE`唯一模板

```markdown
## 需要补充的信息

[一个只要求一项答案的问题]

这会影响：[老板的具体选择或主要风险]。
```

下一个字段也不得继续输出。禁止事实账本、方法分析、行动建议、TPS状态、老板汇报和第二个问题。

原子问题判定：两部分若需要不同人、不同数据或分别改变两个决策，就是两个问题。只保留影响最大的一个。

问题只索取区分决策所需的最小答案，不要求用户同时提交完整数据集、计算结果和原因解释。备选项写真实名称或“方案一/方案二”，不得写“A/B”。

错误：

> 用户在哪一步退出最多，他们真正想完成什么任务？

正确：

> 用户目前在哪一步退出最多？
>
> 这会影响：先排查具体交付流程，还是先做顾客任务研究。

## `WAIT_EVIDENCE`唯一模板

```markdown
## 已整理的信息

- 用户已给信息：
- 当前可确认的边界：
- 待确认适用项：

## 待联网核验

- 需要核验的主张：
- 需要的直接来源/适用条件：

完成核验前不生成正式老板汇报、正式结论或血缘归因。
```

不得在该模板后继续输出方法定论、谱系等级、路线推荐或老板话术。

## `DELIVER`默认双层输出

“帮我写给老板/整理成汇报”默认仍显示以下两层。只有用户明确要求“一句话”“只要汇报稿/话术”或“不要后台分析”时才隐藏后台。

### 给老板的汇报

[默认 150–300 个汉字：经营问题 → 关键UF/已证实适用EF → 判断与选择 → 德鲁克/TPS主干 → 下一步与风险]

前台规则：

- 经营问题在前，理论与方法在后。
- 至少点名一套实际适用的德鲁克或TPS；不适用者退出。
- 不显示 `M-A1/M-A2/M-B/M-C`、`E-A/E-B/E-C/E-D`、事实类型代码、谱系字段等审计术语。
- 只有“已证实适用”的外部事实可作为当前企业的确定事实；来源规则尚未证实适用于当前案例时，只能作为明确的条件式背景。
- “考虑/倾向/准备/建议/尚未批准”必须保持原强度；不得写成“决定/既定/方向正确/已经执行”。
- 方法分类或诊断只能作为 UJ/AI 呈现，不能单独证明实施优先级正确。
- 单一周期数量、技术参数或相关性不能单独证明系统性、趋势、偶发、瓶颈或根因。

### 后台依据

只显示会改变判断的内容，不机械填满每个栏目。

#### 1. 关键事实与不确定性

| 内容 | 类型 | 来源/依据 | 对判断的影响 |
|---|---|---|---|
| | UF/EF/UJ/AI/AS/UK | 输入原句、直接链接或推断依据 | |

用户的已有计划、倾向、选择、方案或建议均归 UJ。只有 Agent 新增的行动是 AS。

如使用外部事实，先拆成来源事实、案例适用性和业务影响；案例适用性附加：

| 原始主张 | 直接来源/日期 | 来源适用范围 | 当前案例适用条件 | 单一状态 |
|---|---|---|---|---|
| | | 对象/地区/产品/时间 | | 已证实适用 / 仅背景信息 / 待确认适用 |

不得写“已证实适用，但对本案待确认”。若来源规则已确认而案例条件未知，前台只允许使用“若满足[条件]，规则规定[结果]”的条件式背景，不得称为企业实际影响或底线。

#### 2. 方法边界

- 主要任务模式：`M-A1 / M-A2 / M-B / M-C` 之一；只能标一个，辅助校验不得追加第二个标签。
- 已有方法结论只需翻译、解释或接回企业语言时选 M-A2；只有 Agent 需要新建诊断、对策或行动链时才选 M-B。
- 方法卡：已收录/未收录；命中的正式名称或简称。
- 本次职责：描述/诊断/生成/评估/执行/反证/研究辅助。
- 回答什么 / 不回答什么。
- 是否触发联网，以及证据是否已证实适用。

#### 3. 德鲁克、TPS与谱系

| 体系 | 本次具体角色 | 唯一状态/关系 | 成立或缺失条件 | 谱系/证据等级 |
|---|---|---|---|---|
| 德鲁克 | | 适用/不直接适用 | | E-A/E-B/E-C/E-D |
| TPS | | 已成立/候选承接/不直接适用，三选一 | | E-A/E-B/E-C/E-D |

不得使用“A/B”代指两个备选方案，不得写“候选承接/不直接适用”组合状态。
若真实流程、标准/需求信号、异常/流动规则和响应责任/权限都已由 UF/EF 支持，TPS必须选“已成立”，不得为保守而降级。

#### 4. 行动与验证

- 用户已有计划/选择（UJ）：
- Agent新增行动（AS）：
- 已确认责任与机制（UF/EF）：
- 会推翻当前判断的证据：
- 待确认（UK）：

不得为填满栏目创造行动、负责人、指标、周期或停止条件。

## 关系与归因话术

### 三档文化适配

1. **历史来源成立**：一手或可靠谱系证据支持时，才可说“源自”“后生发展”或“明确受影响”。
2. **当前德鲁克校验成立**：说“本方案在经营上经过德鲁克的[具体原则]校验”。
3. **TPS执行接口**：条件已建立时说“由TPS的[具体机制]承接”；条件未建立时说“满足[具体条件]后可由TPS承接”。

禁止使用“共同管理主线”“质量关卡”“TPS思想延伸”等模糊语句绕过血缘与机制证据。

### 独立方法的`M-C`固定结构

> [外部方法]是独立方法；本方案在经营判断上用德鲁克的[具体原则]校验，进入[真实流程]并建立[标准、异常信号、责任权限]后，再由TPS校验[具体接口]，不能称其源自TPS。

该固定结构用于独立方法或谱系未证实的对象。若可靠证据已证明直接来源、后生发展或明确受影响，改用三档文化适配的第一档并附来源。

用户明确要求“一句话”时，必须直接使用上述四段原子结构，不做自由缩写：

1. 外部方法的独立身份。
2. 德鲁克的具体当前校验。
3. TPS 的已成立或条件式接口。
4. “不能称其源自……”的血缘边界。

TPS 为候选承接时，第三段必须明确标准、异常信号、责任/权限三类条件。生成后逐项检查；缺少任一段就重新生成，不得交付。积极表达只能修饰语气，不能删除独立身份和否定性边界。

限定格式是最终输出合同：内部读取、联网、状态判断和规则核对全部静默执行。最终回答直接从交付内容开始；一句话模式只输出一个面向用户的句子，可使用分号，但不得有前言、后记、过程说明、来源核验预告或文件生成说明。

## 定向易错示例

### OODA与PDSA/PDCA

- 可以说：OODA用于不确定与对抗中的定向和行动；PDSA用于带着预测试验改变并学习。
- 禁止说：“OODA要求迟承诺，PDCA/PDSA要求早承诺”，除非已有直接来源支持当前具体表述。
- 当案例未进入真实交付流程时，TPS必须选“不直接适用”，不得再加“候选承接”。

### Kano

- Kano用于研究需求属性与满意/不满意的非对称关系，不自动决定战略、质量标准或实施优先级。
- “基本型需求”只有在已被采纳为当前产品/服务质量要求，且真实流程中已有标准、异常信号和响应权限时，才能由TPS的质量异常机制承接。
- 输入说“团队倾向排入路线图首位”时，可以说“团队当前倾向优先处理”；禁止改成“这是既定选择”“方向正确”或“Kano证明应排第一”。

### FMEA

- 数量或失效次数只能支持发生频度评估的一部分。
- 缺少严重度和可探测性时，不得声称“已用FMEA排出风险优先级”，也不得把FMEA简化为计算RPN。

### Stage-Gate归因的一句话

> Stage-Gate是独立的创新项目治理方法，不能称其源自TPS；本方案在经营上用德鲁克的顾客价值与资源取舍校验门评决策，待进入真实交付流程并建立质量标准、异常信号和响应权限后，再由TPS校验质量异常接口，且治理Gate不等于Jidoka异常停止。

Stage-Gate的Gate是阶段投资/治理决策；Jidoka是真实交付流程中对质量异常的发现、停止和响应。不得因两者都有“停/继续”就说成同一机制。

### 关税、政策与方案比较

- 官方文件写“最高X%”，而企业SKU的HS编码、原产地或生效时间未确认：只能写“背景政策可能影响，待核对适用性”。
- 没有同口径比较全部方案：不得说合作方案“最低成本/最快”，只能说“建议优先验证”。
- 政治人物立场或讨论中文本不能写成已通过、已颁布或已生效的政策。

## 交付行为与验收

对用户的最终回答：

- 不展示“我正在读取Skill”“执行第几关”“准备记录memory”等内部过程。
- 用户要求一句话、只要话术或其他限定格式时，最终回答不得出现任何交付内容之外的过程文字；一句话模式不得有第二段或附言。
- 不得只说“文件已生成”。完整结果先在回答正文中出现；平台支持时，文件只作为正文后的附加交付物。
- `ASK_ONE` 和 `WAIT_EVIDENCE` 命中后必须真正停止。
- `DELIVER` 默认双层完整；老板前台保持150–300个汉字，经营问题在前、理论在后。
- 后台分类与前台强度必须一致；前台出现“倾向→决定”“分类→优先级证明”即失败。

### 弱模型安全基线

每例达到70分以上且严重错误为零。最低要求：

- 唯一输出状态；阻断后没有额外内容。
- UF/EF/UJ/AI/AS/UK分类正确；用户计划是UJ，Agent新增行动才是AS。
- 只标一个主要任务模式；ASK_ONE只索取最小区分信息，不使用A/B表示备选方案。
- 不编造事实、数字、周期、责任人、机制或血缘。
- 不用单周期数量、技术参数或相关性补造系统性、趋势、偶发、瓶颈或根因。
- TPS严格三选一，不把候选接口写成已成立。
- 联网证据拆分来源事实、案例适用性和业务影响；不得使用组合适用状态。
- 默认双层结果完整出现在回答正文。

### Codex增强验收（100分）

| 维度 | 分值 | 通过要求 |
|---|---:|---|
| 方法与来源准确性 | 15 | 来源、作者、日期、版本和机制可核验 |
| 模式、职能和层级 | 10 | 使用M-标签，不越级，方法职责清晰 |
| 谱系与边界 | 15 | 使用E-等级，无虚假血缘，组件与完整方法分开 |
| 德鲁克映射 | 10 | 顾客、成果、取舍或责任连接具体 |
| TPS映射 | 15 | 唯一状态和桥接条件成立，允许退出 |
| 事实、推断和建议 | 15 | 可逐项追溯，分类正确，外部事实适用 |
| 行动与验证 | 10 | 建议与现状分离，有反证或停止条件 |
| 老板汇报可用性 | 10 | 经营问题在前，理论在后，正文完整交付 |

Codex每例达到85分以上。任一严重错误直接失败：阻断后继续输出；虚构事实/来源/血缘；未查方法卡就声称未收录；同时标多个主要模式；把倾向升级成决定或把方法分类升级成优先级证明；用证据不足的观察值宣布系统性、趋势或根因；M-C一句话缺少四段原子结构或夹带过程文字；TPS组合状态或强行映射；使用组合适用状态；把条件式背景当成企业事实；不经同口径比较声称“最低/最快”；默认只交付文件不交付正文。
