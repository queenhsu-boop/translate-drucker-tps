# 输出模式与示例

按任务选择最小模板。不要为了完整而机械输出所有栏目；但“回答/不回答、职能与尺度、三轴判断、语义边界”不得被省略到无法审核。

## 安全话术

### A：直接依据

> 本方案直接采用[德鲁克/Toyota一手来源中的明确原则]，并在不改变其核心含义的前提下落实为[具体机制]。

必须附一手来源。只对有直接证据的组件使用 A，不因局部 A 升级整个外部方法。

### B：有据可查的影响或后生发展

> [方法/组件]有资料证明受到[德鲁克/Toyota/TPS]影响或由相关实践发展；本次采用的是[具体机制]，它不等同于[核心体系/支柱]。

必须附谱系证据。“与……相似”本身不能判 B。

### C：独立方法的有界映射

> 本次使用的是[外部方法]。如果用组织熟悉的语言解释，它可帮助我们把[概念]转成[行动]；两者在[独特机制/层级]上并不等同。

> 我们借用[外部方法]处理[它独有的问题]，再用德鲁克/TPS的[原则]校验它是否产生顾客成果或现场改善。

独立外部方法默认从 C 起步；语义高度相似但无血缘证据时仍保持 C。

### D：不支持、冲突或错配

> 该方法在[相似点]上可供参考，但它作用于[对象/层级]，不能替代德鲁克/TPS在[另一对象/层级]上的判断。

> 该方法的[机制/做法]与[德鲁克/TPS原则]存在张力。本次保留[必要机制]，并增加[约束/替代做法]。

## 受众改写

### 面向老板

顺序：经营问题 → 关键约束 → 选择与结果 → 理论定位 → 风险。

> 这次采用[外部工具]解决[它真正回答的问题]，再用[德鲁克/TPS原则]校验顾客成果或执行系统。它不是该体系的原生工具，预期结果由[已确认负责人/待确认]通过[已有证据/待建立基线]验证。

### 面向管理层

顺序：共同成果 → 责任与决策权 → 流程接口 → 证据与复盘。

> 德鲁克语言解决“对什么成果负责”，TPS语言解决“异常在哪里被看见和处理”。[外部方法]负责[独特诊断/设计任务]，其输出进入[责任或流程接口]。

### 面向员工

顺序：场景 → 正常/异常 → 可观察行为 → 反馈与升级。

> 当出现[可观察信号]时，执行[已确认行为]并向[已确认响应角色/待确认角色]反馈。记录用于验证和改进当前方法，不用于惩罚主动暴露问题的人。

### 面向培训

顺序：原判断 → 新判断 → 典型场景 → 练习 → 课后行动 → 主管观察 → 复盘。

培训完成率只表示参与。至少设置一个可观察行为和一个业务结果；基线、目标值和周期未知时标记待确认。

## 示例：OODA 与 TPS

**不建议**：

> OODA是丰田方法论衍生出的现场管理工具。

**建议**：

> OODA是独立的动态决策方法，本次用它缩短异常识别、定向和响应周期；再用 TPS 校验现场落地，包括异常可见、暂停与报告权、及时响应以及处理后的标准更新。两者形成执行衔接，但不存在已证实的历史血缘。

- 谱系：独立体系
- 关系：TPS执行衔接
- 来源置信：方法来源核验后填写
- 摘要：C

## 示例：沃德利地图的情境翻译

**情境结论**：某个已经商品化的基础组件仍由核心团队自建，挤占差异化能力投入。

**建议表达**：

> 这张沃德利地图帮助我们看见：顾客成果所依赖的组件处在不同演化阶段。本次建议不是“按地图自动外包”，而是重新检查稀缺资源是否投入在真正产生顾客差异的能力上；若决定调整，再用 TPS 分析交接后的信息流、质量内建和异常响应。

边界：沃德利地图不等同价值流图，也不能单独证明外包的经济性和风险。

## 示例：审核“A3是TPS原生支柱”

- 原表述：A3是TPS原生支柱。
- 判断：A3与Toyota后生管理和问题解决实践有直接关系，但TPS官方核心支柱是Just-in-Time与Jidoka。
- 谱系：后生发展。
- 关系：与TPS执行衔接。
- 摘要：A3与Toyota关系可判B；“TPS原生支柱”这一主张判D。
- 建议改为：A3是在Toyota实践中发展起来的问题解决与管理学习机制，可用于承接TPS现场改善，但不应称为TPS两大核心支柱之一。
