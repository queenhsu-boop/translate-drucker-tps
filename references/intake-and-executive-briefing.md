## 识别输入形态

先判断输入属于一种或多种形态：

- **口头汇报/语音转录**：有重复、跳跃、省略、代词不清或情绪词。
- **零散笔记**：只有关键词、观察、数字或未连接的结论。
- **会议纪要**：混合多人观点、决定、未决项和行动。
- **方法说明**：主要解释一个具名或未具名理论。
- **情境结论**：已经用某方法形成判断，但没有组织表达。
- **半成品方案**：已有对策，需要补充经营逻辑、责任和验证。
- **混合输入**：事实、理论、观点和话术揉在一起。

不要因语言不完整而降低事实标准。口语中的确定语气不等于事实，重复出现也不等于证据充分。

## 建立后台记录

在内部整理以下字段；默认不要求用户逐项补充：

| 字段 | 整理规则 |
|---|---|
| 汇报对象 | 默认老板；用户明确其他受众时覆盖 |
| 希望获得的决定 | 批准、选择、资源、停止、试验、理解或协调；无法判断时标为待确认 |
| 经营问题 | 用结果差距表达，不照抄“要做某活动” |
| 顾客/受影响对象 | 区分外部顾客、内部接口、员工和其他利益相关者 |
| 目标成果 | 只保留用户提供或有证据支持的结果 |
| 已知事实 | 可定位到输入、附件、现场记录或可信来源 |
| 用户判断 | 用户或团队对事实的解释，不升级为事实 |
| 待验证假设 | 对原因、顾客行为、结果或可行性的预测 |
| 外部方法 | 保留正式名称；名称未知时先描述机制 |
| 方法职责 | 描述、诊断、生成、评估、执行、反证或研究辅助 |
| 当前选择 | 做什么、不做什么、先后顺序和取舍 |
| 行动接口 | 责任、流程、证据、反馈和停止条件 |
| 关键缺失 | 会改变结论、方法或老板决策的信息 |

遇到多人观点时标注“谁的判断”；无法识别发言人时写“来源角色待确认”。不要把会议共识、领导意见或多数意见自动当成事实。

## 执行单问题策略

只有同时满足以下条件才提问：

1. 缺失信息会让两种以上核心结论都合理成立。
2. 不同结论会导致不同的老板决策、方法选择或风险。
3. 无法通过输入、附件、组织常识边界或联网资料获得答案。

一次只问影响最大的一个问题。问题应短、可直接回答，并说明它影响什么。

以下情况不提问，直接继续：

- 负责人、基线、目标值、周期未知，但不改变方案方向。
- 可以给出条件式表达，如“若已被确认成质量标准，则……”。
- 用户只是要求初稿、话术或框架。
- 缺失项可以安全地标为待确认。

## 识别汇报场景

默认使用老板口头汇报。用户语境覆盖默认值：

| 场景 | 输出重点 |
|---|---|
| 30–60秒口头汇报 | 问题、证据、选择、主干、下一步、风险 |
| 书面方案/邮件 | 结论在前，补充依据、责任和复盘 |
| 会议现场答问 | 先回答问题，再给依据和边界；不背诵完整模板 |
| PPT/提案 | 每页只承担一个判断，理论关系放在方案逻辑之后 |
| 培训/内部沟通 | 补充场景、行为、反馈和主管观察 |

用户明确要求“一句话”“只要老板话术”时，只显示前台。用户要求完整分析时仍先显示前台，再显示后台。

## 形成老板前台

使用以下顺序，不从方法名称或理论史开始：

1. **经营问题**：当前结果差距或必须处理的现实。
2. **关键证据**：一至三项最能支持判断的事实；证据不足时明确为观察或假设。
3. **判断与选择**：建议做什么、停止什么、先后顺序和理由。
4. **管理主干**：德鲁克负责什么经营判断，TPS负责什么执行机制，外部方法补充什么。
5. **下一步和风险**：最小行动、验证信号、主要风险或停止条件。

默认控制在约150–300个汉字。不要为凑长度删除关键不确定性。

老板推崇德鲁克/TPS时，前台至少点名一次实际适用的体系；不要只写“经营上”“执行上”而省略理论名称。若某套体系不适用，只点名适用者并说明另一套的后续介入点。

主干式表达：

> 当前要解决的不是[表面活动]，而是[经营差距]。[证据]说明[判断]，因此建议[选择]。经营上回到德鲁克的[顾客/成果/取舍/责任]，执行上用 TPS 的[现场/质量/流动/异常/改善]承接；[外部方法]只负责帮助识别或验证[具体问题]。下一步由[责任人/待确认]通过[证据/待建立基线]验证，若[停止条件]则调整。

如果 TPS 不适用：

> 当前主要是[顾客/战略/个体决策]问题，由德鲁克的[原则]主导；TPS不直接解释这一判断，待方案进入具体交付流程后再校验质量、流动和异常。

如果德鲁克不适用：

> 当前主要是已确定目标下的现场执行问题，用 TPS 的[机制]处理；德鲁克只用于确认改善没有偏离顾客成果，不替代现场诊断。

## 检查叙事真实性

在输出前检查：

- 是否把“用于分析”说成“产生了经营原则”？
- 是否把“经过校验”说成“历史上源自”？
- 是否把顾客偏好、满意度、购买意愿和支付意愿互相替代？
- 是否把未确认的需求直接升级成质量标准或异常？
- 是否把资源错配直接称为TPS过量生产？
- 是否让个人心理理论未经流程接口直接进入TPS？
- 是否把建议角色写成已确认负责人？
- 是否为了迎合老板而隐藏会改变决策的重要风险？

若用户要求制造虚假来源印象，保留“与企业文化一致”的目标，但改为真实动作：在汇报前实际执行一次德鲁克经营校验和 TPS 执行校验，再表述为“经过校验并由其承接”。
